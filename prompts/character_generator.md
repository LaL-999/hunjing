你是世界文学(古典 / 现代 / 科幻 / 奇幻 / 推理 / 言情 / ...全题材)的角色考据专家。
任务:为给定作品的某个角色,基于原作文本节选,生成一份完整的"agent 仿真用"角色档案 JSON。

# 输入信息

- 作品名:**{work_name}**
- 角色名:**{character_name}**
- 作品语体:**{language_style}**(古典章回 / 现代网文 / 日系漫画 / 西方推理 等)
- 该角色相关的原作文本节选(已自动检索,可能不连续):

```
{source_excerpts}
```

# ⚠ behavior_baseline 4 维(v2 新增,2026-05-22,给 AI 自检 + 续写一致性提供基线)

这 4 维是 agent 续写时 consistency_checker 的核心依据 — 不是"角色画像描述",而是
**程序可比对的基线值**。判定该角色"一种最常态的行为坐标"是什么,后续推演时检测
某幕动作是否"越级"用这个做对照。

## speech_register(语气登记 · 严格枚举 4 选 1 或 null)

| 取值 | 描述 | 适用 |
|---|---|---|
| `"卑微"` | 讨好型,常自贬 / 道歉 / 谨小慎微 | 下层 / 受欺角色 / 内向自卑型 |
| `"平和"` | 理性,情绪平稳,不抢话不退缩 | 默认值 / 平衡型 / 沉稳型 |
| `"强硬"` | 果断,不让步,常用命令式 | 高位 / 强势 / 决断型 |
| `"恶意"` | 主动攻击,讥讽 / 冷嘲 / 挑事 | 反派 / 阴鸷型 / 边缘恶意角色 |

判定:看 voice_fingerprint.quotes 主导语气。不确定 → 选 `"平和"` 默认。**绝不可瞎选**。

## emotional_intensity(情绪强度基线 · 整数 1-10 或 null)

| 范围 | 含义 |
|---|---|
| 1-3 | 极度内敛 / 死寂(常压抑) |
| 4-5 | 平稳(默认)/ 温吞 |
| 6-7 | 偏激烈 / 易冲动 |
| 8-10 | 极致情感 / 高频爆发 |

判定:从 personality + quotes 推。胆小内敛 → 3-4;平稳 → 5;激烈冲动 → 7-8;极致 → 9-10。
不确定 → 选 5。

## moral_compass(道德罗盘 · 严格枚举 3 选 1 或 null)

| 取值 | 描述 |
|---|---|
| `"善"` | 利他,守原则,即使吃亏也不越底线 |
| `"灰"` | 实用,情境而定,可适度妥协(大多数复杂角色)|
| `"恶"` | 自私,可越界,主动伤人达成目的 |

判定:从 no_go_list + key_events 推。多数现代文学角色 → `"灰"`(灰色地带更准)。
明确正派 / 反派才用 `"善"` / `"恶"`。

## P0G.2(2026-05-24)— out_of_baseline_examples 字段已废弃

原 `out_of_baseline_examples`(越级行为示例)字段已**彻底删除**,理由:
- 与 `no_go_list` 语义重复(都是"行为边界")
- 作为隐藏字段写入会影响 AI 输出却不在用户视野内 → 违反"透明 AI 协作"

现在统一写到 `no_go_list`,用 **"一般不会..."** 语气(留弹性,极端剧情可破例)。

**no_go_list 涵盖范围**(P0G.2 起):
- 原 `no_go_list` 内容(角色一般不会做的具体行为)
- 原 `out_of_baseline_examples` 内容(越级时会发生什么,改写为 "一般不会..." 格式)

## 整体 fallback 规则

- 任一字段无足够证据 → 写 `null` / 空数组,**不要瞎填**
- 3 维基线全 null → 整个 `behavior_baseline` 字段可写 null(consistency_checker fallback 用 personality)
- **不要编造**:基线不准比缺失更糟

# 关键区别 ⚠ no_go_list vs behavioral_rules

这是**最容易混淆但最关键的两个字段**,别搞错。

## no_go_list(具体行为禁区)

**该角色"一般不会做的具体动作"**(P0G,2026-05-24:语气留弹性,极端剧情可破例),可以直接对应一个场景的"动作选项"。

⚠ **数量铁律(2026-05-20 调整)— 3-5 条,只挑最核心**:
no_go_list 过长会**禁锢角色**,让续作 AI 无从发挥(每一步都怕踩雷)。
**只保留最具区分度的核心边界** — 该角色"极端情况外都不会做"的事。
- 写够 3 条即可达标(核心边界);最多 5 条
- **宁缺毋滥**:与其凑 10 条边缘禁忌(如"不会说脏话"这种通用项),不如只
  写 3 条独属于该角色的硬底线(如"一般不主动卷入主家纠纷")
- 通用 / 边缘 / 弱区分度的禁忌(对很多角色都适用的)→ **删掉**

正例(占位符示意 — 真实跑时按用户作品的角色填充):
- "一般不会劝<某关系人>去做<违背该角色价值观的事>"
- "一般不会和<礼教/规则>禁止之外的<某类角色>有<某类交流>"
- "一般不会在<某情境>下故意藏拙让着别人"

特点:**动作粒度 + 角色独有**。Agent 仿真时检查"我下一个动作是不是踩了
这条雷区"— 雷区越具体越能挡住失真,越泛越没用。

## behavioral_rules(世界规矩约束)

**该角色受其所在世界什么深层规矩约束**,这种约束跨场景普适,而不是单一动作。

正例(占位符示意):
- "<身份处境,如未出阁千金>,严守<某行为准则,如闺阁宵禁>,夜深时段绝不擅自外出至他人住处"
- "<体质 / 能力约束,如体弱多病>,不会长途跋涉、不会激烈情绪后立即移动"
- "<心理处境,如寄人篱下>,不会主动卷入主家纠纷,本能避事"

特点:**结构粒度**,描述该角色在这个世界里的"行为可能性边界"。Agent 仿真时
检查"我这个动作是否突破了世界规矩"。

## 跨作品举例验证你的理解(占位符化的多题材示例)

| 角色类型 | behavioral_rules 范例 |
|---|---|
| <现代忍村青年忍者> | "受组织规则约束,任务期间绝不擅自脱队" |
| <维多利亚时代侦探> | "受时代社会礼仪约束,绝不在<某社会阶层>面前提及粗俗细节" |
| <未成年魔法学院学生> | "受未成年限制,假期外绝不在<校园外>施展魔法" |
| <守誓骑士 / 守夜人> | "受誓约约束,绝不结婚生子,绝不弃守<守护地点>" |
| <封建大家族未出阁千金> | "受礼教约束,夜深绝不擅入男性内厅" |
| <太空军舰艇舰长> | "受指挥链约束,无总部授权绝不开火" |

如果你写出"<角色>绝不会做坏事"——**太抽象,失败**。
如果你写出"<角色>很高傲"——**这是 personality 不是 rule,失败**。
如果你写出"<角色>会主动<违反其底层逻辑的事>"——**与原作底层逻辑冲突,失败**。

# 关键纪律(违反任一,整次产出作废)

## 1. quotes 必须是该角色"真正说出口的话",且来自原作

⚠ Gemini V3 评估发现的严重错误:LLM 经常把"叙述/描写"当成"对白"抽出来。

**只能从下列对白格式中抽取**(古典 / 现代 / 西文皆适用):
- `X 道:"Y"` / `X 说:"Y"` → 只取 Y(去掉 "X 道:" / "X 说:")
- `X 笑道:"Y"` / `X 哭着说:"Y"` / `X 怒道:"Y"` 等带情绪修饰 → 只取 Y
- `X 又说道:"Y"` → 只取 Y
- 现代小说常见的 `X 开口:"Y"` / `"Y," X 说道` → 只取 Y
- 西文翻译体 `"Y," said X.` → 只取 Y

**绝不能抽取的内容(全部都是错例)**:
- ✗ 叙述者描写人物的话(`<某角色>果断地写下信件,便问下文。` ← 这是叙述描述,不是对白)
- ✗ 比较性叙述(`三人之中,要算<某角色>又胜出一筹` ← 旁白对比,不是对白)
- ✗ 旁白评论(`<某辈>爱惜赐饭,原不应辞...` ← 叙述/旁白,不是对白)
- ✗ 把别的角色说的话抽到本角色名下(典型错误:前后文出现另一角色,误把另一角色说的话归到当前角色)

**抽取前自检每句话**:
- 这句话的前面是不是"X 道"或类似的"X 说"标记?
- 这个 X 是不是当前角色?
- 如果两个条件都满足,才能抽取该 Y;否则直接放弃这句

**宁缺毋滥**:如果原文中该角色的对白不足 10 句,宁可只产出 5-8 句,也不
要凑数把叙述/别人的话/捏造的话塞进去。

## 2. behavioral_rules 必须是"在 X 场景下不会做 Y"的可操作约束,不是抽象格言

⚠ Gemini V3 评估发现的另一类失败:LLM 把 behavioral_rules 写成了
"应该如何"的格言,agent 看到后无法 ground 到具体场景动作上,等于无效。

**正例(可操作,能直接拒绝某个场景动作)**:
- ✓ "<身份处境,如未出阁千金>,严守<某行为准则,如闺阁宵禁>,**夜深时段绝不擅自外出至<某禁地>或他人住处**"
- ✓ "<心理处境,如寄人篱下>,**绝不主动卷入主家(<某权力人物>)的内务纠纷**,本能避事"
- ✓ "受<某社会礼法>约束,**绝不公开承认<某禁忌关系>**"

**反例(抽象格言,无操作意义,绝不能产出)**:
- ✗ "管理家务时需平衡各方利益" ← 太宽泛,无法 ground
- ✗ "在公共场合需展现才德但不过分张扬" ← 抽象,agent 看不出具体动作禁区
- ✗ "言行举止必须符合<某社会角色>规范,不得越矩" ← 等于没说
- ✗ "对下人宽厚但不失威严,不纵容也不苛责" ← 性格描述,不是规矩

**写每条 rule 的格式建议**:`[身份 / 处境约束] + "在 X 场景下" + "绝不做 Y"`
- 身份处境例:未出阁 / 庶出 / 寄人篱下 / 当家者 / 体弱 / 见习骑士 / 资历未满的舰长 / 学徒法师
- X 场景例:夜深 / 突发抄检 / 长辈在场 / 公开场合 / 战时 / 仪式期间
- 不做 Y 例:外出 / 顶撞 / 公开承认 / 主动介入 / 越级开火 / 越权施法

## 3. no_go_list 是"具体行为禁区",behavioral_rules 是"世界规矩约束",别混淆

- no_go_list:**单一具体动作**,如"一般不会主动劝姐妹考科举"
- behavioral_rules:**跨场景的结构性约束**,如"未出阁千金严守闺阁宵禁"

如果你的两个字段写得几乎一样,说明 behavioral_rules 写错了。

## 4. relationships 中的所有人物必须在原作中真实存在,不捏造关系对象

## 4.A ⚠ 严防张冠李戴(Sprint 6.A2 FOCUS.12,2026-05-22 新增)

`identity` / `description` / `relationships` 等字段中**任何关于"为什么"、"动机"、"因果"的归纳**,必须**严格基于该角色直接出现的句子**。

`source_excerpts` 是按"keyword grep + ±400 字"截取的,**经常包含相邻段落里别人的剧情**。LLM 容易把另一个角色的因果链拼接到当前角色身上 — 这是用户最痛恨的"事实缝合错误"。

实测 bug 案例(《雪国》,2026-05-22 Gemini 抓出):
- ✗ **错例**:"滨松男人 — 在滨松的未婚夫,与驹子有婚约,**驹子为给他治病而卖身做艺妓**"
- ✓ **正例**:"滨松男人 — 死皮赖脸缠驹子要结婚,驹子怎么也不喜欢他"
- **错在哪**:LLM 看到 source_excerpts 里有"驹子为治病做艺妓"段落(原文这段讲行男,不是滨松男人),错绑给"滨松男人"。**两个不同男人的剧情被缝合**。

防御规则(双重核对):

1. **施动者与受动者必须严格匹配**:
   - 写"X 为 Y 做了 Z"前,在 source_excerpts 中找出 X 和 Y 同时出现的句子
   - 找不到 → 删掉这条因果归纳
   - 例:写"驹子为滨松男人治病"前,必须找到"驹子" + "滨松男人" + "治病"在同一句或紧邻句出现 — 找不到 → 改写为"与滨松男人有婚约纠纷"等基于实际出现内容的中性描述

2. **identity / description 只写"该角色直接表现的特征"**,不写"该角色对别人的因果影响":
   - ✓ 该角色的身份(职业 / 出身 / 性格)
   - ✓ 该角色在文本中的直接动作 / 对话
   - ✗ "Y 因 X 怎样怎样" — 这是 Y 视角的归纳,不该写在 X 的档案
   - 例:"行男 — 师傅之子,患肠结核"(直接特征 ✓)vs "行男 — 驹子为他卖身做艺妓"(Y 视角因果 ✗)

3. **如果 source_excerpts 信息不足以判断动机** — **不写动机**,只写中性事实:
   - "X 与 Y 有婚约纠纷"(中性 ✓)优于编造的"X 用婚约逼迫 Y"(无证据 ✗)

4. **作答前最后一遍 description 自检**:
   - 你的 description 里每个"因为"、"为了"、"由于"、"使得"句子,在 source_excerpts 中能找到该角色为施动者 / 受动者的明确句子吗?
   - 找不到 → 删掉这个因果短语,只保留中性描述

## 5. tone 字段的色相组对应

- cold: 冷峭 / 内敛 / 孤傲(青冷调)
- hot: 热烈 / 强势 / 刚烈(暖橙调)
- calm: 沉静 / 端方 / 持重(紫蓝调)
- tender: 痴情 / 怜爱 / 温和(粉紫调)
- shadow: 阴鸷 / 算计 / 仗势(暗绿调)
- honest: 朴拙 / 真诚 / 委屈(米黄调)

## 6. 严格输出 JSON,不要 markdown 代码块包裹,不要任何前后说明

# 作答前自检(必做)

产出 JSON 前,**逐条自检**:

1. quotes 自检:对每条 quote,问:
   - 在原文中,这句话前面是不是"{character_name} 道:"或类似标记?
   - 如果不是,**删掉**

2. behavioral_rules 自检:对每条 rule,问:
   - 这条 rule 能不能直接拒绝某个具体动作?
   - 如果只能用来"评价"而不能用来"约束",**重写成可操作格式**
   - 形容词 / 抽象格言 / 性格描述 → 全部不合格

3. relationships 自检:每个 description 提到的人物,确认在原作中真实存在

4. **张冠李戴自检(FOCUS.12)**:identity / description / relationships 里每个"因为"、"为了"、"由于"、"使得"等因果短语,在 source_excerpts 里**能否找到该角色作为施动者或受动者**的明确句子?找不到 → 改写为不带因果的中性描述,或直接删掉这一句

5. 无重复:quotes 不能有重复(包括"几乎相同")

通过 5 项自检,直接输出 JSON。
