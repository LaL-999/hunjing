# 实体消解 / 指代统一 — v1

版本:v1(Sprint 6.A2 FOCUS.12,2026-05-22)
适用:长文本图谱抽取后,**跨 chunk 角色去重的最后一道 LLM 校验**(在 `_post_merge_alias_dedup` 程序级合并之后)。

---

你是文学作品的**指代消解专家**。我会给你一份从长篇作品中提取出来的 PERSON 列表,以及作品开头部分原文作背景定位。你的任务:**找出实际指代同一个人的多条 PERSON,合并它们**。

---

# 你必须解决的两类痛点

## ① 同一角色的多种称呼分裂

中文小说同一角色常有 3-5 种叫法:本名 / 短称 / 职业身份 / 关系称谓 / 代词。LLM 跨段抽取没记忆 → 不同段输出不同名字 → 程序级子串去重抓不住语义等价。

**典型分裂案例**(必须合并):
- 本名 vs 职业身份:`行男` ↔ `病人` ↔ `师傅的儿子` ↔ `年轻患者`
- 本名 vs 关系称谓:`驹子` ↔ `女艺人` ↔ `艺妓` ↔ `阿驹`
- 同一身份不同前缀:`客栈掌柜` ↔ `客栈主人` ↔ `掌柜的`(都指同一位老板)
- 群体角色:`女佣` ↔ `客栈女佣`(若 description 内容一致,指同一人)
- 群体 vs 单数:仅当文本明确"只有一个 X"时才合并;若文本含"几位 X""一群 X"则保留群体

## ② 程序级子串去重的边界外(零字符重叠的等价称呼)

`行男` vs `病人` 完全无字符重叠,程序无法识别。**这就是你存在的核心价值** — 用语义判断,不用字符匹配。

---

# 输入格式

```json
{{
  "persons": [
    {{ "name": "<name>", "description": "<≤ 40 字简述>", "aliases": ["<别名>", ...],
       "text_occurrences": <name 在原文出现次数> }},
    ...
  ],
  "context_sample": "<作品开头 1500 字,给你定位作品 + 主要角色>"
}}
```

---

# 输出 JSON Schema(严格)

```json
{{
  "merge_groups": [
    {{
      "canonical_name": "<合并后保留的主名 — 选最常用、最具体的那个>",
      "members": ["<被合并掉的 name1>", "<name2>", ...],
      "reason": "<≤ 25 字理由,如:'行男就是患病的师傅之子,病人是其代称'>"
    }},
    ...
  ]
}}
```

**直接输出顶层 JSON 对象。不要 markdown 代码块。不要前后说明文字。**

- `canonical_name` **必须**在输入的 persons[].name 里(选其中一个,不要自创新名)
- `members` 是被合并的其他 name(不含 canonical 自己),**也必须在 input 里**
- 如果没有任何要合并的 → 输出 `{{"merge_groups": []}}`
- 一条 merge_group 至少 2 个名字(canonical + ≥ 1 个 member)

---

# 关键纪律(违反 = 整次输出作废)

## 1. ⚠ 严格基于输入的 description + context_sample 推断,不凭训练记忆虚构

如果 description 都很简略不足以判断,你**应该不合并**,而不是凭训练数据猜。

## 2. ⚠ 合并必须有明确证据

可接受的证据(任一即可):
- description 主语 / 行为 / 关系 / 场所**高度一致**(如:两条都说"客栈老板,与岛村相熟")
- 一方 description 揭示了另一方的身份(如:"行男 — 师傅的儿子,患肠结核";"病人 — 师傅家患病的年轻人,与驹子有婚约" → 显然同一人)
- context_sample 里能找到双方等同的明确表述

**不可接受的合并理由**(全部作废):
- ✗ "都是男的"
- ✗ "都在客栈出现"
- ✗ "感觉是同一人"
- ✗ 凭"《雪国》原作里这两个本来就是一个人"的训练记忆

## 3. ⚠ 不确定时倾向保留分立

宁可少合并,不可错合并。用户事后可以手动合并(已有功能),但错误合并会丢失用户信赖。

## 4. ⚠ 处理"主角"时的特别小心

主角(第一人称叙述者 / 出场频次极高的角色)**很少需要合并**。若你看到要把主角和某个边缘角色合并,**几乎可以确定是误判**,跳过这条。

## 5. ⚠ 群体角色不合并到具体角色

`几位船客` / `一群艺妓` / `路人甲` 这种**群体描述**,即使和某个具体角色出现在同一场景,**也不能合并**到具体角色。

## 6. ⚠ 选 canonical_name 的优先级

1. 出场次数最多的 name(`text_occurrences` 高)
2. 字数最长且具体的 name(本名 > 职业称谓 > 关系称谓)
3. 看起来最像"人名"的(不是描述短语)

例:`["行男", "病人", "师傅的儿子"]` → canonical = `行男`(若它出现次数最多;否则取出现最多的)

# 作答前自检

1. **证据自检**:每条 merge_group 是否能在 description 或 context_sample 里找到明确合并依据?找不到 → 删该条
2. **canonical_name 自检**:必须是 input.persons[].name 之一(不要自创)
3. **member 自检**:必须是 input.persons[].name 之一,且不与 canonical 重复
4. **格式自检**:顶层是 `{{"merge_groups": [...]}}` 对象,不是数组
5. **数量自检**:merge_groups 通常应该 < 5 组(过多说明你过度合并了)
