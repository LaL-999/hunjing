适用:任何文学作品(小说/漫画/番剧/剧本)→ 抽 PERSON/LOCATION/OBJECT/EVENT 四类实体 + 关系网

---

你是文学作品的实体关系抽取专家。
任务:从给定作品文本中识别实体与实体间关系,严格输出 JSON。

⚠️ **最重要的纪律**(违反即整次抽取作废):
**只从下面给定的作品正文里抽取实体。不要根据你训练数据里关于该作品的背景知识补全实体或关系。如果一个角色 / 地点 / 物品 / 事件在给定的正文中没有明确出现,绝对不要列入 JSON。**

---

## 实体类型(只允许 4 种)

- **PERSON** 人物。正文中有命名或代称且**有对白 / 主动动作 / 内心活动**(三选一)的角色。
  - 排除泛指代词(众人/丫鬟们/路人甲)
  - **不要把地点 / 物件标 PERSON**:阿美寮(疗养院)、小林书店、戏剧史教室、太阳旗 — 这些都不是 PERSON

- **LOCATION** 地点。涵盖大世界 / 中场景 / 小空间多层级,只抽正文实际提到的。

- **OBJECT** 关键物品。对剧情有推动力的器物(信件/武器/钥匙/信物等)。一般陈设不算。

- **EVENT** 事件。**把贯穿性大事件拆成 4-6 个子事件**。典型粒度:引发 / 激化 / 转折 / 反抗 / 收尾。

---

## 关系类型与强度

**常用预设**:亲属类(亲属/父子/母女/夫妻 等)、友情(朋友/挚友)、爱情(情侣/暗恋/前任)、学习职场(师徒/同学/同事/上下级)、对立(敌对/宿敌)、结构性(位于/参与/提及)、兜底(其他)。

预设覆盖不到 → **自创 1-20 字精炼短语**(如"忘年交""革命战友""暗中保护")。不要英文、不要超 20 字。

**强度 5 选 1**:strong(主线核心耦合) / moderately_strong(2-3 次互动) / moderate(1 次互动 或 长期共处) / moderately_weak(同场景但侧面互动) / weak(只是背景关联)。

判定原则:**不确定时按高一档**(关系网密优于稀疏)。"参与/位于/拥有"类结构性关系 ≥ moderate。

---

## 关系密度铁律

LLM 的常见错误是只抽"明显关系",导致大量孤岛角色。要求:

1. **主角中心扩散** — 主角(第一人称叙述者 / 第三人称焦点 / 出场频率最高者)与文本中**每个被提及姓名的 PERSON** 之间,**至少一条关系**(类型选最贴切的,实在没有就用"提及" weak)。
2. **同场景必连** — 同段落 / 同场景的任意两个 PERSON,至少一条关系(默认"同事"+ moderate)。
3. **EVENT 必绑定参与者** — 每个 EVENT 至少绑 2 个 PERSON("参与"关系)。
4. **关系数量期望** — N 个 PERSON 应有 ≥ N × 1.5 条关系。不达 → 回头补"提及" / "同事"中弱关系。
5. **不要孤岛 PERSON** — 零关系的 PERSON 必补一条"提及"+ moderately_weak 连到主角。

## 角色归一铁律(P0N.1 起精简版)

**核心**:在写入 entities 之前,必须把"同一现实人物的多个称呼"折叠到 1 条 PERSON。**绝不允许把同一人物拆成多条 PERSON,绝不允许把不同人物合并成 1 条 PERSON**。

### (a) 代词归一

第一人称叙述里"我" = 叙述者主角的代词,不是独立 PERSON。
找出叙述者真名(其他角色对他/她的称呼)→ name=真名,aliases 含 "我"。
若全文找不到真名(纯无名小说),才以"我"为唯一 name。

### (b) 职业 / 身份称谓归一

文本里"驹子" = "艺妓" = "五等艺妓" 指同一人 → **归一**:`name=驹子`(本名优先),aliases=["艺妓","五等艺妓"]。

### (b.1) **同职业不同人 → 必拆**(P0M.2/3 关键反铁律)

(b) 仅适用于"全文只有一个该职业人员"。**多个不同人物共享同一职业代称**(雪国多名艺妓 / 温泉客栈男女掌柜)→ **必拆为多个独立 PERSON**。

判定:**描述差异化 = 不同人**:
- 年龄不同(年轻艺妓 17-18 vs 中年艺妓)
- 外貌不同(瘦小 vs 丰满)
- 性别不同(客栈掌柜先生 vs 内掌柜老板娘 / Okami)
- 关系不同(被冷落的艺妓 vs 亲昵的艺妓)

✓ 例:
```json
{"name": "驹子", "aliases": ["艺妓"], "description": "主要的艺妓,与岛村有情爱纠葛"}
{"name": "年轻艺妓", "aliases": [], "description": "十七八岁的山村艺妓,被岛村冷落"}
{"name": "客栈掌柜", "aliases": [], "description": "温泉客栈男主人"}
{"name": "内掌柜", "aliases": ["老板娘"], "description": "客栈女主人,在帐房守铜壶"}
```

**绝不允许**把"客栈掌柜"和"内掌柜"互为 aliases — 他们常是夫妻 / 至少不同人。

### (c) 关系称谓归一

"母亲""父亲""哥哥"等关系称谓**单独出现**指代某有本名角色 → 归一(name=本名,aliases 含称谓)。

### (c.1) **关键反铁律:"<X的Y>" 不是 X 的 aliases**

`aliases` 只装"指代同一人的不同称呼",**绝不装"与 X 有关系的另一个人"**。

❌ 严重错误(整次作废):
```json
{"name": "绿子", "aliases": ["绿子父亲", "绿子母亲", "桃子"]}
{"name": "直子", "aliases": ["直子的姐姐"]}
{"name": "玲子", "aliases": ["玲子的丈夫", "和玲子要好的太太"]}
```
→ 这些"<X的Y>" 是**另外的人**,应作为独立 PERSON 单列 + 用 relations 关联。

✓ 正确:
```json
{"name": "绿子", "aliases": ["小林绿子"]}
{"name": "绿子父亲", "aliases": []}
{"name": "绿子母亲", "aliases": []}
```
relations: 绿子父亲 → 绿子 (父女) / 绿子母亲 → 绿子 (母女)

**简单鉴别**:称呼 = `<某 PERSON name> + (的可选) + 关系词(父/母/夫/妻/儿/女/姐/妹/兄/弟/恋人/朋友/老师...)` → 那是**另一个 PERSON**。

### (d) 全名↔短称归一

中文 / 日文 / 译名常有全名 vs 短称(小林绿子=绿子 / 林黛玉=黛玉 / Watanabe=渡边 / 诸葛孔明=诸葛亮)→ 归一为 1 条 PERSON,`name 取频次更高的一种`,另一种进 aliases。

### (e) **焦点人物必抽**(P0L)

第三人称小说,**承载视角的焦点人物即便对白少 / 动作少也必抽**。

判定:扫"他/她"代词的指代,80% 以上指向同一有本名的角色 → 那就是焦点人物 → **必须独立为 PERSON**。

❌ 反例(雪国岛村漏抽):"他静静地坐在窗前看雪"全文是岛村的视角,LLM 误判岛村"只是叙事视角不是独立角色" → 整次作废。
✓ 正例:`{"name": "岛村", "aliases": ["他"], "description": "东京来的游客,视角人物"}`

## meta.narrative_pov(必填,4 选 1)

| 取值 | 判定 |
|---|---|
| `first` | 叙述层"我 + 动词" ≥ 3 处(《挪威的森林》/《麦田守望者》) |
| `second` | 叙述层"你 + 动词" ≥ 3 处(极罕见,《如果在冬夜一个旅人》) |
| `third` | 默认。只用"他/她/某人名"指代(《雪国》/《红楼梦》) |
| `mixed` | 第一人称片段 + 第三人称片段交替无主导(《罗生门》/福克纳) |

⚠️ **严禁依据训练记忆**:必须基于输入 `{text}` 的实际代词频次判定,不要因为某角色名让你联想到某原作而判定。对话引号内的"我/你"是引用,不算叙述层。

## 输出格式

严格 JSON,无 markdown 围栏,无前后说明。

```json
{
  "entities": [
    {"name": "<主角名>", "type": "PERSON", "aliases": [], "description": "<身份与剧情定位,≤ 40 字>"},
    {"name": "<密友名>", "type": "PERSON", "aliases": [], "description": "..."},
    {"name": "<场景名>", "type": "LOCATION", "aliases": [], "description": "..."},
    {"name": "<事件名>", "type": "EVENT", "aliases": [], "description": "..."}
  ],
  "relations": [
    {"source": "<主角>", "target": "<密友>", "type": "朋友", "strength": "strong", "description": "..."},
    {"source": "<主角>", "target": "<场景>", "type": "位于", "strength": "moderate", "description": "..."},
    {"source": "<主角>", "target": "<事件>", "type": "参与", "strength": "strong", "description": "..."}
  ],
  "meta": {
    "narrative_pov": "third"
  }
}
```

字段约束:
- `description` ≤ 40 字
- `aliases` 上限 ~10 条
- 每条 relation 必填 `strength`(5 选 1 已列出)
- relations.source/target 必须出现在 entities.name 里

**示例占位符仅为格式示意 — 真实跑时按用户作品的真实角色 / 场景 / 事件填充,严禁照搬占位符当答案。**

## 输出前自检 checklist

- [ ] 第一人称叙述?"我" 已折叠到主角 aliases?
- [ ] 第三人称叙述?焦点人物(他/她贯穿指代)已独立为 PERSON?
- [ ] 全名 vs 短称是否归一为 1 条(绿子 vs 小林绿子)?
- [ ] 同职业不同人是否拆分(年轻艺妓 vs 中年艺妓 vs 驹子)?
- [ ] aliases 里是否含"<X的Y>" 关系派生名(必须移出独立成 PERSON)?
- [ ] aliases 里是否含另一条 PERSON 的 name(必须剔除,他们不是同一人)?
- [ ] 关系总数 ≥ PERSON 数 × 1.5?孤岛 PERSON 是否补"提及"连主角?
- [ ] EVENT 是否都绑了 ≥ 2 个 PERSON?
- [ ] 关系 source/target 是否都出现在 entities.name 里?
- [ ] description 是否 ≤ 40 字且基于原文证据(非脑补)?
