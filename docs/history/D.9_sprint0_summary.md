## 关键洞察(决定 D.9 设计走向)

### 1. **L2 单层一致性远超 ADR v3 预期** ⭐

Test 1 实测:**纯 t2i 无 ref + 详细 prompt 描述符** → Qwen-VL 评 **95/100 同一人**。

ADR v3 §4.2 原预期:L2 单层 80-85%。**实测高 10 分**。

**含义**:
- D.9 实际一致性应**上调到 92-95%**(原预期 85-92%)
- L3 ref image 不再是关键路径 — vendor 是否支持都不影响
- 4 层方案 实际是 **L1+L2+L4 三层够用**,L3 锦上添花

**ADR 校准建议**:
- §4.2 L2 行:"单层 70-80%" → **"单层 90-95%"**
- §4.5 UI chip:"约 92% 一致" → **"约 95% 一致"**
- §9 风险表:"L3 vendor 不支持" 风险等级从 🟡 降到 🟢

### 2. **Qwen-VL Max 多模态视觉 DNA 提取完美** ⭐

Test 2 实测:3 张同画风(国漫工笔半厚涂)不同内容图,Qwen-VL 在 6 个核心视觉字段
(笔触/上色/线稿/比例/光影/构图)上达到 **100% 一致识别**。

**含义**:
- 画风定调员 v2 多模态升级**完全可行**
- 用户上传 3 张参考图后,Qwen-VL 能稳定提取视觉 DNA,DeepSeek 综合的详细 prompt 有可靠基础
- 不需要 fallback 到 v1 流程(LLM 纯文字推 5 风格)

### 3. **素材库抽取员产物质量整体过关,角色字段仍有空间** ⭐

Test 3 实测:1057 字红楼梦节选 →
- 角色:3 个,**63.3%** 字段填空率
- 场景:5 个,**100%** 字段填空率
- 道具:6 个,**100%** 字段填空率
- 平均:**87.8%** → 🟢 可用

**角色字段填空率低的原因**:原文对每个角色描述深度不一(主角描述深,配角少)。
D.9 实施时,Agent #5 抽取后用 character_focus 流程让用户补字段。

**ADR 校准建议**:
- ADR v3 §3.2 Agent #5 中,字段未明 → 填 "(原文未明)" + 用户对焦补字段。
  此机制已设计,**不需修订**。

## 顺带发现的问题(D.9 启动前要解决)

### A. Seedream 系列模型版本管理

实测发现:
- `doubao-seedream-3-0-t2i-250415` — 账户列表能看到,但调用 404(deprecated)
- `doubao-seededit-3-0-i2i-250628` — 调用 404
- `doubao-seedream-4-0-250828` — ✅ 可用
- `doubao-seedream-5-0-260128` — ✅ 可用

**含义**:火山方舟会**下线旧版本**(model list 残留可见但不可调)。D.9 实施时需要:
- **`scripts/d8_evaluate.py` 加 healthcheck**:实际调一次 test prompt 确认模型可用
- **`pricing.py` 加 model 状态字段**(active / deprecated)
- **错误兜底**:404 → 自动 fallback 到下一个可用 Seedream 版本

### B. Qwen-VL JSON 解析 100% 成功

测试中所有 Qwen-VL 输出都是合法 JSON,**无解析失败**。说明:
- 不需要 `_repair_llm_json` 兜底(D.7.A 已为 DeepSeek 加过)
- 但 D.9 实施时仍建议保留同样的 markdown fence 剥离 + JSON 修复(与 llm_client 一致风格)

### C. D.9 实施工作量建议下调

ADR v3 §2.1 预估 **14-16 sprint**。Sprint 0 验证后:
- L3 ref image 不必死磕(原预估占 0.5-1 sprint),省 0.5 sprint
- 素材库抽取员 prompt 不需 v2 调优,直接按 ADR v3 写就够
- **建议下调到 13-15 sprint**
