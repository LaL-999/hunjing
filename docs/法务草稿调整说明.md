# I. doc 8(用户协议草稿)修改清单

## 改动 1:第四条新增"主动监测义务"(红旗原则)— P0

### 修改位置

`doc 8` → 第二章 → 第四条 "平台对上传内容的处理规则"

### 现状问题

现有第四条四项(最小化原则 / 指纹拦截 / 不存档不分发 / 主动响应投诉)中,
**指纹拦截只是被动响应,没有体现"主动监测"**。

### 律师原话

> 国内司法实践(如近期"AI 生成奥特曼"案)明确倾向于认定:**生成式 AI
> 服务提供者不是单纯的技术工具方,而是内容的生成者或共同生成者**。
> 工具中立抗辩 + 尽到合理审核义务,两者结合才能有效降低平台责任。

### 建议修改方向(供签约律师细化措辞)

将原第二项扩展为:

```
第二项,主动监测义务(红旗原则)。

我们建立并按月迭代主流网络文学平台、出版机构作品的版权指纹库,
覆盖范围至少包括:
- 起点中文网、晋江文学城月度榜前【500-1000】部作品
- 主流出版社近【5】年出版的有版权登记作品
- 知名 IP 改编影视、漫画、游戏的原作

当用户上传的内容与指纹库匹配度 ≥ 【85%】时,系统自动拦截,要求用户
提供合法持有的证明材料(如电子书购买凭证、授权书),否则不予解析。

此外,我们对生成内容部署关键词监测,如出现明显版权侵权风险标识
(出版社名称、原作者姓名、知名 IP 关键词组合),将自动触发人工审查流程。
```

### 建议律师特别审视

- 指纹库覆盖标准应"做到什么程度算合理审核义务" — 律师需根据**当前司法判例**给出
  量化建议(覆盖前 500 / 前 1000 / 全网?)
- 关键词监测的执行边界 — 避免误拦截合法用户
- 红旗原则触发后的"后续处理流程"是否需要写入协议

## 改动 3:新增"未成年人保护"专条 — P0

### 修改位置

`doc 8` → 第四章后,作为新增第八章 / 或并入现有用户行为章

### 现状问题

**完全没有未成年人保护条款**。

### 律师原话

> 如果不做限制,必须接入标准的未成年人防沉迷和内容过滤接口。如果想低成本合规,
> 建议在注册/支付环节强制设置"我已满 18 周岁"的勾选声明,并在协议中明确
> "本平台不向未成年人提供服务,如发现将做退款封号处理"。

### 建议修改方向

```
第 X 条:未成年人保护

第一项:本服务**不向未成年人提供**。我们认定 18 周岁以下的自然人为
未成年人。

第二项:注册环节

  该勾选记录由系统永久保存,作为您注册时年龄声明的电子证据。

  (1) 关闭账户、删除其上传与生成数据

  (3) 由用户虚假声明引发的法律责任(包括但不限于监护人索赔),
      由用户及其监护人独立承担

第四项:本协议所有条款均以本条为前提。任何与未成年人保护要求冲突的
内容约定,均归于无效。
```

律师明确指出:接入"防沉迷标准接口"是高成本路径;"18+ 勾选 + 协议明示 + 发现退款封号"

## 改动 7:新增"数据出境与第三方模型调用"条款 — P1

### 修改位置

`doc 8` → 第六章 隐私与数据 → 第十三条之后,作为第十三条之一

### 现状问题

协议没有覆盖 LLM API 调用的数据流向。律师强烈建议 MVP 阶段只用国内备案大模型,
但协议需要预留未来切换境外模型的合规路径。

### 律师原话

> 如果向 Claude/OpenAI 传输国内用户的原文和个人数据,**绝对会触发数据出境
> 安全评估**。在初创 MVP 阶段,强烈建议仅使用国内已备案的大模型。

### 建议修改方向

```
第十三条之一:数据出境与第三方模型调用

第一项:当前实施
  本服务所使用的全部大语言模型均为依《生成式人工智能服务管理暂行办法》
  在中华人民共和国境内备案的模型(如 DeepSeek、Qwen 等国内模型)。
  您的上传内容、生成内容、个人信息均**不涉及出境**。

第二项:未来变更程序
  如未来本服务需调用境外大模型(如出于服务质量优化等原因),我们将:
  (1) 按《数据出境安全评估办法》完成相应评估或备案
  (2) 以独立弹窗形式向您说明数据跨境流向,取得您的单独同意
  (3) 您未同意时,我们将继续以纯境内模型为您提供服务,不影响您的
      会员权益与已购订阅期内的服务标准

第三项:数据最小化
  即使采用境内模型的情况下,我们仅向模型 API 传送必要的处理数据
  (如解析所需的文本片段、推演所需的角色档案数据),不传送以下内容:
  - 您的真实身份标识(姓名、身份证、人脸)
  - 您的账户登录凭证
  - 您的支付信息
  - 与当前服务请求无关的其他历史数据
```

### 工程含义(对未来产品决策的约束)

- MVP 阶段**绝不使用 OpenAI / Claude API**,即使能让 Composer 质量从 Gemini 1.5 → 5+
- 这是**合规优先于产品质量**的硬选择
- Phase E 关于"切 Claude Sonnet 4.5 突破质量天花板"的方案**已被律师否决**

# II. doc 11(法务第六条修订版)修改清单

## 改动 2:第六条第二项 — 价格 / 配额调整改为"老用户老办法" — P0

### 修改位置

`doc 11` → 第六条 → 第二项 "分级与价格的外部引用"

### 现状问题

doc 11 第二项写的"提前 30 日通知 + 既有订阅期不受影响 + 不接受可退订"——**律师明确
指出这不够**。

### 律师原话

> 对于已订阅且在服务期内的用户,**不能通过提前 30 天通知就强制绑定新版本**。必须
> 做到"老用户老办法,新用户新办法",或者在老用户续费时强制弹窗要求重新确认。
> 单方面在服务期内改变核心对价,即使赋予了退订权,**也极易被消保委认定为霸王条款**。

### 建议修改方向(原第二项重写)

```
第二项 v2:分级与价格的外部引用 + 调整机制

本服务的具体分级、订阅价格、各档位对应的算力配额、各档位包含的功能权益,
详见单独发布的《浑晶服务等级与价格说明》。价格说明是本协议不可分割的
组成部分,其条款与本协议具有同等法律效力。

我们保留对价格说明做以下三类调整的权利,但调整规则严格如下:

类别 1 — 对您有利的调整(降价、配额上调、权益扩增):
  立即对所有用户(含老用户)生效,无需事先通知

类别 2 — 对您不利的调整(涨价、配额下调、权益缩减):
  **老用户老办法,新用户新办法**:
  (1) 已订阅且在服务期内的用户,**继续享受订阅时锁定的服务标准**,
      直至该订阅期(月费 1 个月,年费 1 年)自然结束
  (2) 老用户在订阅期满**续费时**,系统将以独立弹窗形式向您展示新版
      价格说明并要求您重新勾选确认,确认后续费方按新版生效
  (3) 我们承诺在不利调整生效前【30】日通过平台公告 + 站内信 + 邮件
      至少两种方式通知所有用户

类别 3 — 算力配额换算系数调整(因模型供应商成本波动):
  (1) 单次调整不超过【20%】,年累计不超过【50%】
  (2) 受影响的老用户在调整生效后,可任选:
      - 维持原换算系数至当期订阅自然结束
      - 立即按比例退回未消耗款项并停止订阅

第三项及以下保持原文不变。
```

### 工程含义

后端必须支持**订阅快照**:用户付费时把当时的"价格说明版本号 + 各档位配额数字"冻结
进用户档案,执行时按订阅时的版本而非当前版本计费。

# III. 律师确认现状有效的部分(签约律师无需重做方向性判断)

下面这些内容已得律师方向性确认,**签约律师只做措辞细节优化,不要重做业务理解**:

## 1. 用户上传声明 + 勾选机制(对内追偿足够,无需 + 人脸识别)

律师原话:
